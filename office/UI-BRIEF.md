# AI 직원 사무실 — UI 설계 브리프

Stitch 등 디자인 도구에 넘기는 화면 사양서. 실제 동작하는 웹앱(로컬 :3010)의 구조·기능을 그대로 옮긴 것.

## 무엇인가

1인 사용자("사장님")가 부서별 AI 직원에게 업무를 지시하고 결과를 보고받는 **사내 인트라넷형 단일 페이지 웹앱**. 각 부서에는 실장 1명과 직원 2~6명이 있고, 실장이 지시를 받아 직원에게 위임한다. 직원이 실제 도구(파일 읽기, 웹 검색, git, DB 조회 등)를 실행하며, 삭제·병합처럼 되돌릴 수 없는 작업은 사장님의 **PIN 결재**를 받아야만 실행된다.

데스크톱 우선. 모바일은 1열로 접힌다.

## 화면 구조

세로로 5층. 가로 최대폭 1280px, 가운데 정렬.

```
[1] 헤더        — 회사명 · 작업 상태 · 보관 메모 건수
[2] 부서 탭     — 비서실 / 개발실 / 물커톤실  (안읽음 배지)
[3] PR 집계판   — 물커톤실에서만 보임
[4] 본문 2열    — 좌: 사무실 현황(넓게)  |  우: 사내 메신저(고정폭 360px)
[5] 부서 게시판 — 전체폭, 팀 공유 메모 카드들
```

## [1] 헤더

- 좌: `연성 비서실`
- 우: 작업 상태 — 대기 중이면 `○ 대기중`(흐리게), 직원이 일하는 중이면 `● 작업중`(강조색). 그 옆에 `보관 메모 3건`

## [2] 부서 탭

- 부서 3개. 선택된 탭만 강조.
- 다른 부서에 안 읽은 메시지가 있으면 탭 이름 옆에 숫자 배지.

## [3] PR 집계판 (물커톤실 전용)

해커톤 팀원별 기여도 리더보드. 가로로 나열되는 칩.

- 제목 `PR 집계`
- 칩 예시: `🏆 정연성 PR 12개 · 기여 58%` / `홍길동 PR 8개 · 기여 42%`
- 1등 칩만 강조. 데이터가 없으면 `채팅에 이름을 남기면 여기에 올라갑니다`

## [4-좌] 사무실 현황

**이 영역이 이 앱의 정체성이다.** 부서에 소속된 직원들이 "지금 자리에 있는지, 무슨 일을 하는지"를 한눈에 보여준다. 표현 방식은 자유롭게 제안해도 좋다(자리 배치도, 재실 현황 보드, 상태 카드 등).

각 직원마다 보여야 하는 것:

- 이름 (예: `기록 담당`, `코드 점검관`, `통합 담당`)
- 담당 업무 한 줄 (예: `메모를 저장·조회·삭제한다`)
- 배정된 AI 모델 (예: `Opus 4.8`, `Haiku 4.5`) — 작게, 보조 정보로
- 고유 색상 (직원마다 다름, 아바타/점/라벨에 사용)
- 현재 상태 4가지: **대기 중 / 작업 중 / 자리 비움(휴식) / 결재 대기**
- 작업 중일 때는 지금 실행 중인 도구를 짧게 (예: `웹 검색 중`, `git diff 검토 중`, `메모 저장 중`)

실장은 다른 직원보다 위계가 위라는 게 드러나야 한다.

### 실제 부서·직원 명단

- **비서실** — 실장 / 기록 담당(Haiku 4.5) · 조사 담당(Opus 4.8) · 아카이버 담당(Haiku 4.5)
- **개발실** — 개발실장 / 기획 담당 · 문서 점검관 · 스펙 점검관 · 제출 점검관 · 코드 점검관 · 통합 담당
- **물커톤실** — 물커톤 실장 / 전략 담당 · 제출 점검관 · 코드 점검관 · 통합 담당(Haiku 4.5)

## [4-우] 사내 메신저

부서와의 대화창. 고정폭.

- **헤더**: `사내 메신저 — 부서 직통`
- **세션 바**: `세션` 라벨 + 드롭다운(대화 여러 개 저장됨) + `＋ 새 세션` + 삭제 아이콘
- **대화 로그** — 말풍선이 아니라 **업무 기록/로그 형태**. 줄 종류:
  - 내 지시 — 발신자 `나`
  - 실장/직원 답변 — 발신자가 직원 이름, 각자 고유 색
  - 위임 — `실장 → 기록 담당` 형태의 지시 전달
  - 보고 — 직원이 실장에게 올리는 결과
  - 도구 로그 — 회색 한 줄, 예: `📁 메모 저장: 물커톤-대회정보`, `🔍 git diff`, `🔗 링크 확인: …`
  - 시스템/오류 줄
  - 첨부파일 링크 칩
- **결재 카드** (아래 별도 설명)
- **입력줄**: `나>` + 텍스트 입력(`지시 사항을 입력하세요`) + 📎 첨부 버튼 + `전달` 버튼

## 결재 카드 — 가장 중요한 컴포넌트

직원이 위험한 작업(메모 삭제, 스크랩 삭제, git 병합, git push)을 시도하면 대화 로그 안에 끼어드는 승인 카드. **실제 사내 전자결재 문서처럼** 보여야 한다.

포함 요소:

- 제목 `〈 결재 요청 〉` + 기안한 직원 이름
- 요청 내용 한 줄 (예: `보관 메모 삭제 (과외비 정산)`, `병합 요청: feature/login`)
- **PIN 입력칸** — 4~6자리, 마스킹. 브라우저 팝업이 아니라 카드 안에 있어야 한다
- 버튼 2개: `승인 〔印〕` (위험/강조), `반려` (약하게)
- 결재가 끝나면 버튼이 사라지고 **도장이 찍힌 상태**로 바뀐다: `〔승 인〕` 또는 `〔반 려〕`, 시간 초과 시 `〔시한 경과 · 자동 반려〕`
- 승인/반려/대기 세 상태가 시각적으로 확실히 구분돼야 한다

## [5] 부서 게시판

- 헤더 `부서 게시판 — 팀 공유 메모`
- 메모 카드 여러 장이 가로로 흐름. 각 카드: 본문 + 하단에 작성자·시간 + 삭제 버튼
- 하단 입력줄: `팀원 모두에게 보이는 메모를 남기세요` + `붙이기` 버튼
- 비었을 때 안내 문구

## 디자인 방향

- **다크 테마**. 사내 인트라넷/전자결재 시스템의 격식과 신뢰감.
- 참고 색: 깊은 네이비 `#0d1424` / 패널 `#141b2e` / 골드 포인트 `#c9a227` / 결재 도장 인주색 `#b23b2e`. 문서·메모류는 크림색 종이(`#f5f3ee`)로 대비를 준다.
- 타이포: 제목은 명조(세리프)로 공문서 느낌, 본문은 깔끔한 고딕(산세리프).
- **모든 UI 텍스트는 한국어.** 위에 적힌 문구를 그대로 쓸 것. 영어로 바꾸지 말 것.

### 만들지 말 것

- 슬레이트 회색 + 크게 둥근 모서리 카드 + 보라/파랑 그라데이션 버튼의 전형적인 AI SaaS 대시보드
- 픽셀아트·도트·8비트 게임 그래픽
- 네온/사이버펑크 색상
- 의미 없는 통계 타일(큰 숫자 + 작은 라벨) 나열
