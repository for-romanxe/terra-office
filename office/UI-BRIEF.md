# TERRA 연구실 — 화면 설계 브리프 (Stitch용)

실제로 돌아가는 웹앱(로컬 `:3010`)의 **구조·기능**을 그대로 옮긴 사양서. 화면을 다시 디자인할 때 이 구조를 기준으로 삼는다. 색·폰트 같은 비주얼은 자유롭게 제안해도 되지만, **부서 구성·화면 블록·캐릭터 동작 흐름**은 앱이 이미 그렇게 작동하므로 바꾸지 않는다.

> 캐릭터(사람)가 명령에 따라 걸어다니고 타자 치는 애니메이션은 **이미 만들어져 있다.** 이 문서의 "캐릭터 동작" 절은 그걸 새로 만들라는 게 아니라, 지금 어떤 순서로 움직이는지 알려주는 것 — 화면을 다시 짜도 이 동선이 들어갈 자리를 비워두라는 뜻이다.

---

## 무엇인가

1인 리더("사장")와 그 팀원(이사·본부장)이 **부서별 AI 직원**에게 업무를 지시하고 결과를 보고받는 **사내 인트라넷형 단일 페이지 웹앱.** 부서마다 실장 1명과 직원 2~6명이 있고, 실장이 지시를 받아 직원에게 위임한다. 직원이 실제 도구(파일 읽기·웹 검색·git·DB 조회 등)를 실행하고, 삭제·병합처럼 되돌릴 수 없는 작업은 사장의 **결재**를 받아야만 실행된다.

부서는 **비서실 · 개발실 · 물커톤실** 세 개. 왼쪽 탭으로 전환하며, 어느 탭이든 화면 골격은 같고 내용물(직원·테마·일부 패널)만 다르다.

데스크톱 우선. 모바일은 1열로 접힌다.

## 화면 골격 (세 부서 공통)

```
┌──────────────┬───────────────────────────────────────────────┐
│  사이드바     │  헤더: [부서명]  |  ○ 대기중 / ● 업무중        │
│              ├──────────────────────────┬────────────────────┤
│  로고        │                          │                    │
│  사원증      │   사무실 전경            │   사내 메신저       │
│  ┌────────┐  │   (아이소메트릭 SVG,     │   (세션 드롭다운    │
│  │ 비서실 │  │    사람이 걸어다니는     │    + 채팅 로그      │
│  │ 개발실 │  │    장면)                 │    + 결재 카드      │
│  │물커톤실│  │                          │    + 입력창 📎)     │
│  └────────┘  ├──────────────────────────┤                    │
│              │   직원 현황 (범례:       │                    │
│  PR 집계판   │    이름·모델·상태)        │                    │
│  (물커톤실만)├──────────────────────────┴────────────────────┤
│              │   PM 봇 알림창 (물커톤실만 — 깃허브 push/PR)   │
│  메모함       ├───────────────────────────────────────────────┤
│  (사장만)     │   부서 게시판 (사람끼리 붙이는 압정 메모)       │
│              │                                               │
│  보관 메모 n건│                                               │
└──────────────┴───────────────────────────────────────────────┘
```

### 블록별 설명

| 블록 | 내용 | 표시 조건 |
|---|---|---|
| **사원증** | 로그인한 사람의 직급 뱃지 + 이름 + 퇴근 버튼 | 로그인 후 |
| **부서 탭** | 비서실 / 개발실 / 물커톤실 (아이콘 + 이름) | 비서실 탭은 사장에게만 보임 |
| **PR 집계판** | 팀원별 push 개수 + 기여도 %, 1등 🏆 | 물커톤실 활성 시 |
| **메모함** | 직원이 남긴 노트 목록 (제목 + 미리보기), ＋로 추가 | 사장에게만 보임 |
| **헤더 상태칩** | 그 부서가 일하는 중이면 `● 업무중`, 아니면 `○ 대기중` | 항상 |
| **사무실 전경** | 부서 직원들이 자리에 앉아 있는 아이소메트릭 SVG 장면 | 항상 |
| **직원 현황(범례)** | 직원 카드 그리드 — 이름·담당·모델·현재 상태 | 항상 |
| **사내 메신저** | 세션 선택 + 채팅 로그 + 결재 카드 + 입력창(파일 첨부) | 항상 |
| **PM 봇 알림창** | 깃허브 활동(push·PR·merge) 전용 다크 패널 | 물커톤실만 |
| **부서 게시판** | 사람끼리 직접 쓰는 압정 메모 (AI 호출 없음) | 항상 |

## 부서 1 — 비서실

평상시 업무. **사장 전용** — 이사·본부장에게는 탭 자체가 안 보이고, 개인 메모리를 다루기 때문에 접근이 막힌다.

| 순서 | 직원 | 모델 | 담당 |
|:---:|---|---|---|
| — | **실장** | Opus 4.8 | 지시 접수 → 위임 → 결과 취합·보고 |
| 1 | 기록 담당 | Haiku 4.5 | 메모 저장·조회·삭제(삭제는 결재), 사장 배경·첨부파일 열람 |
| 2 | 조사 담당 | Opus 4.8 | 웹 검색으로 최신 정보·뉴스·사실 확인 |
| 3 | 아카이버 담당 | Haiku 4.5 | 대외활동 아카이버 앱의 공고 스크랩·활동 기록 관리(삭제는 결재) |

**특징**: PM 봇 없음, PR 집계판 없음. 사이드바 메모함이 이 부서의 노트와 연결된다.

---

## 부서 2 — 개발실

해커톤·대회용 개발 부서. 팀원 6명 — **점검관 4명 + 통합 1명 + 기획 1명.** 점검관들은 **읽기 전용 도구만** 가져서, 시키지 않는 한 코드를 못 고친다(권한으로 강제).

| 순서 | 직원 | 담당 |
|:---:|---|---|
| — | **개발실장** | 커밋 전 코드 점검관 검토 필수, 치명 결함 발견 시 커밋 중단 |
| 1 | 코드 점검관 | 버그·보안·예외처리·컨벤션 문제 적발 (읽기 전용) |
| 2 | 통합 담당 | 커밋·브랜치·병합·푸시 (유일한 쓰기 권한, 병합·푸시는 결재) |
| 3 | 스펙 점검관 | 요구사항 대비 구현의 누락·불일치·엣지케이스 점검 (읽기 전용) |
| 4 | 제출 점검관 | 대회 제출 요건(산출물·README·링크·규정) 충족 여부 |
| 5 | 문서 점검관 | 기획서·발표자료·README의 오탈자·논리·전달력 (읽기 전용) |
| 6 | 기획 담당 | PRD·프리모템·우선순위 등 기획 문서 작성 |

**특징**: PM 봇 없음, PR 집계판 없음. 벽 색이 비서실과 다르다(짙은 청색 계열).

## 부서 3 — 물커톤실

물커톤(MOVE-AI 물류 해커톤) 대회 전용. 개발실과 **병렬로 돌아간다**(대회 중 병목 방지). 팀원 4명 — 개발실의 압축판 + 전략 담당.

| 순서 | 직원 | 모델 | 담당 |
|:---:|---|---|---|
| — | **물커톤 실장** | Opus 4.8 | 대회 전용 총괄 |
| 1 | 전략 담당 | Opus 4.8 | 대회정보 노트 관리(삭제는 결재) + 리서치·PRD·우선순위 |
| 2 | 코드 점검관 | Opus 4.8 | 코드·팀원 브랜치·깃허브 PR 점검 (읽기 전용) |
| 3 | 제출 점검관 | Opus 4.8 | 제출 요건 충족 여부 점검 |
| 4 | 통합 담당 | Haiku 4.5 | 커밋·브랜치·병합·푸시 (병합·푸시는 결재) |

**특징 (다른 두 부서와 결정적으로 다름):**
- **실험실 테마** — 방 팔레트가 연구실 컨셉(푸른 벽·타일·스틸 책상). 직원 소품도 실험실 분위기.
- **PR 집계판** — 사이드바에 팀원별 push 개수 + 기여도 %(1등 🏆).
- **PM 봇 알림창** — 사무실 전경 아래에 깃허브 활동 전용 **다크 패널**. 팀원이 push하거나 PR을 열면, 그리고 결재를 통과해 실제로 병합·푸시가 실행되면 여기에 색깔별로 쌓인다(push 골드 / PR 시안 / merge 그린).

## 캐릭터 동작 (이미 만들어진 애니메이션의 동선)

사무실 전경 안의 사람들은 **명령이 오면 아래 순서로 움직인다.** 화면을 다시 디자인해도 이 동선이 벌어질 공간 — 실장 책상, 그 앞의 "보고 자리", 직원 책상들, 그 사이 통로 — 은 유지되어야 한다.

**공간 배치**
- 실장은 **앞줄 가운데 책상**에 앉는다. 그 바로 앞이 **보고 자리**(직원이 지시받고 보고하러 오는 곳).
- 직원들은 각자 **자기 책상**에 앉아 있다(연차 순으로 자리 배정).
- 두 책상 줄 사이에 **통로**가 있고, 가구를 뚫지 않도록 사람은 통로를 경유해 ㄱ자로 걷는다.
- 구석에 **자료실 캐비닛 · 탕비실 · 유리 회의실 · 출입구**가 있다.

**명령 한 번의 흐름**

| 단계 | 누가 | 동작 | 말풍선 |
|---|---|---|---|
| ① 접수 | 실장 | 자기 책상에서 생각 | "음… 생각 중" |
| ② 위임 | 해당 직원 | 자리 → **보고 자리**로 걸어옴 | 실장: `지시 — "…"` / 직원: "알겠습니다!" |
| ③ 복귀 | 직원 | 보고 자리 → 자기 책상 | — |
| ④ 작업 | 직원 | 자기 책상에서 타자(도구에 따라 **캐비닛**까지 다녀오기도) | 실행 중인 도구 이름 (상태: 업무중) |
| ⑤ 보고 | 직원 | 자리 → **보고 자리** | `보고 — "…"` |
| ⑥ 복귀 | 직원 | 보고 자리 → 자기 책상 | — |
| ⑦ 총괄보고 | 실장 | 자기 책상에서 | "보고드립니다!" |

**결재가 필요한 작업일 때** (④ 도중): 직원이 보고 자리로 와서 "결재 부탁드립니다!"라고 서서 기다린다 → 메신저에 결재 카드가 뜬다 → 승인되면 "결재 감사합니다!" 하고 자리로 복귀, 반려되면 "알겠습니다, 취소하겠습니다…".

**한가할 때** (지시가 없을 때): 직원 아무나 가끔 **흡연 부스**나 **탕비실 커피**로 잠깐 다녀온다(6~12초). 일이 들어오면 즉시 자리로 복귀.

**직원 상태 3종** (범례·본인 위에 표시):
- `대기 중` — 자리에 앉아 있음
- `업무중` — 도구 실행 중 (무슨 작업인지 말풍선)
- `결재 대기` — 사장 승인을 기다리는 중

> 접근성: "동작 줄이기(reduced motion)"가 켜져 있으면 걷는 애니메이션 없이 **순간 이동**한다. 이 경우에도 자리·상태·말풍선은 동일하게 표시된다.

## 사내 메신저 상세

- **세션** — 한 부서 안에 여러 대화방(세션)을 두고 드롭다운으로 전환. ＋로 새 세션, 🗑로 삭제(사장만).
- **채팅 줄 종류**
  - 사람이 보낸 지시 — 이름 앞에 **직급 꼬리표**(사장/이사/본부장)
  - `실장 → 직원 (업무 위임)` — 들여쓴 회색 한 줄 로그
  - `🛠 도구 이름` — 직원이 실행한 도구 로그
  - 직원 보고 — 직원 이름 + 본인 색
  - 실장 총괄 보고
- **결재 카드** — 승인〔印〕/ 반려 버튼. **사장 화면에만** 버튼이 있고, 이사·본부장에게는 "사장님 결재 대기 중" 안내만. 5분 무응답 시 자동 반려.
- **입력창** — 텍스트 + 📎 파일 첨부(10MB 이하). 텍스트 파일은 직원이 내용까지 읽고, 나머지는 공유·다운로드용.
- **알림** — 다른 창을 보고 있을 때 보고·결재가 오면 소리 + 시스템 알림 + 탭 제목에 📬.

## 권한 (직급별)

사장 > 이사 > 본부장 > AI 직원. 이사·본부장은 **권한이 동일**하다(칭호만 다름).

| | 사장 | 이사 | 본부장 |
|---|:---:|:---:|:---:|
| 지시 · 게시판 · 세션 생성 | ○ | ○ | ○ |
| 결재 승인 | ○ | ✕ | ✕ |
| 비서실 · 메모함 | ○ | ✕ | ✕ |
| 세션 삭제 | ○ | ✕ | ✕ |
| 남의 게시판 메모 떼기 | ○ | 자기 것만 | 자기 것만 |

로그인은 이름 선택 + 개인 접속 코드. 사장 자리(로컬 접속)는 코드 없이 통과.
